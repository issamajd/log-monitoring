Data handling

Local-first with controlled enrichment and redaction

The monitoring system will see sensitive operational data. The default must keep data on the customer site, redact secrets, and use read-only access for enrichment.

Redaction policy

  • Store full SQL text, but redact parameter values.
  • Redact passwords, tokens, API keys, connection-string credentials, and obvious secret fields.
  • Extract safe searchable fields from SQL: operation, tables/entities, duration, rows affected, and risk flags.
  • Keep raw unredacted data out of Elasticsearch unless explicitly approved for a controlled diagnostic case.
  • Test redaction with real log samples before production use.

Session enrichment

  • `SessionID` is the primary support correlation key.
  • The system can connect read-only to SQL Server to resolve session context.
  • Enrichment should cache lookups and avoid heavy queries against the app database.
  • Customer can disable DB enrichment if required.
  • Only safe support fields should be copied into monitoring storage.

Forwarding policy

Default deployment is customer-site only. Optional forwarding exists only for support cases that need it.

Data class Default location Forwarding rule
Errors and health summaries Customer site Can be forwarded when enabled and redacted.
Slow operation summaries Customer site Can be forwarded as metadata and durations.
SQL text Customer site Forward only redacted SQL and only when needed.
SQL parameters Not stored as raw values Do not forward raw parameter values.
User/session context Customer site Forward only safe identifiers or approved fields.

Access and configuration

  • Use a read-only SQL Server account for session enrichment.
  • Store monitoring credentials outside source control and outside public dashboard exports.
  • Separate support/operator access from admin access in Grafana.
  • Keep retention and forwarding configurable per customer.
  • Log monitoring-system changes such as retention updates, forwarding enablement, and alert changes.
Security posture The system should help support without becoming a second production database full of secrets. The safe default is redacted, local, read-only, and configurable.
